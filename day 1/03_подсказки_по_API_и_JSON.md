# Подсказки по API и JSON — день 1

Откройте этот файл, когда дойдёте до `dispatcher.py`. Здесь показаны части решения, которые можно соединить самостоятельно.

## Цепочка запроса

```text
Текст в браузере → POST /api/classify → classify(text)
→ chat(messages) → AllTokens → текст ответа модели
→ проверка JSON → ответ браузеру
```

Файл `alltokens.py` уже отправляет запрос. В нём ключ читается из переменной окружения на сервере. Браузер не должен обращаться к AllTokens напрямую.

## Два сообщения для модели

```python
messages = [
    {"role": "system", "content": "Здесь ваши правила и формат JSON"},
    {"role": "user", "content": text},
]
response = chat(messages)
```

В `system`-сообщении перечислите **все** допустимые категории, правило высокого приоритета, когда спрашивать уточнение и точный формат ответа. Низкая `temperature` в готовом коде уменьшает вариативность, но не гарантирует правильный формат.

## Где находится ответ

```python
content = response["choices"][0]["message"]["content"]
```

`content` — строка. Даже если внутри написано `{...}`, это ещё не словарь Python. Разберите её:

```python
import json
data = json.loads(content)
```

Не используйте `eval`: он исполняет текст как код. Если модель добавила пояснение или вернула сломанный JSON, `json.loads` выдаст ошибку — это честная ошибка обработки.

## Проверка результата

```python
if not isinstance(data, dict):
    raise ValueError("Ответ модели должен быть JSON-объектом")
if data.get("category") not in CATEGORIES:
    raise ValueError("Модель вернула неизвестную категорию")
if data.get("priority") not in PRIORITIES:
    raise ValueError("Модель вернула неизвестный приоритет")
if not isinstance(data.get("question"), str):
    raise ValueError("Уточняющий вопрос должен быть строкой")
```

Верните словарь только с тремя ожидаемыми полями. Если получите ошибку, посмотрите сообщение на странице и в терминале. Сообщение об ошибке API вроде 401 или 402 покажите наставнику; оно может быть связано с ключом или балансом, а не с вашим промптом.
