# ИИ-диспетчер обращений — занятие 1

**Группа C · 120 минут · команда 3–4 человека · один компьютер на команду**

Сегодня вы создадите первую работающую часть приложения: по тексту вымышленного обращения оно получит от ИИ категорию, приоритет и, если нужно, уточняющий вопрос. В конце занятия покажите наставнику один живой ответ AllTokens.

## Что у вас есть

Наставник выдаёт архив `day1-student-pack.zip`. В нём уже есть веб-страница, локальный сервер и код для отправки запроса в AllTokens. Ваша главная работа сегодня — придумать точные правила и дописать `dispatcher.py`. Ключ к API вводит наставник на сервере. **Не вставляйте ключ в код, браузер, чат или репозиторий.** Используйте только вымышленные обращения без имён и контактов.

## Маршрут занятия

| Время | Что сделать | Что показать |
|---|---|---|
| 0–15 мин | Прочитайте правила, распределите роли и откройте файлы. | Каждый знает свой результат на сегодня. |
| 15–35 мин | Запустите проект и отправьте одно обращение в учебном режиме. | Страница открыта, ответ появился в таблице. |
| 35–55 мин | Разберите примеры и запишите спорные правила. | Есть выбранные категории и критерий высокого приоритета. |
| 55–85 мин | Допишите инструкцию модели и обработку JSON в `dispatcher.py`. | Сервер принимает результат только в нужном формате. |
| 85–100 мин | Вместе с наставником включите живой вызов AllTokens. | Один живой ответ виден на странице. |
| 100–120 мин | Проверьте 2–3 разных обращения, исправьте обнаруженную ошибку и заполните рабочий лист. | Показ: обычный случай и случай с уточнением. |

Если этап занял меньше времени, переходите дальше. Если не получается установить Python или Flask за 5 минут, позовите наставника.

## Шаг 1. Запустите заготовку

Распакуйте архив в отдельную папку. Откройте эту папку в редакторе кода и терминале. На macOS или Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
python3 app.py
```

На Windows PowerShell:

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
py -m pip install -r requirements.txt
py app.py
```

Откройте `http://127.0.0.1:5000`. Введите «Не работает проектор». Пока вы видите учебный ответ `другое / обычный`: это нормально. Остановить сервер можно клавишами `Ctrl+C` в терминале.

## Шаг 2. Договоритесь о правилах

Откройте `cases_training.json`. В нём 12 вымышленных обращений с эталонными ответами. Пользуйтесь следующими правилами:

| Категория | Когда выбирать |
|---|---|
| `техника` | Компьютер, проектор, принтер, звук. |
| `сеть` | Интернет, Wi-Fi, вход в школьный сервис. |
| `помещение` | Свет, мебель, дверь, температура. |
| `другое` | Остальное или непонятное. |

Приоритет `высокий` ставьте, только если **прямо сейчас нельзя провести занятие** или проблема **затронула несколько кабинетов**. Иначе — `обычный`. Если непонятно, что случилось или где, нужен **один короткий вопрос**. Отсутствующие детали нельзя выдумывать.

Найдите хотя бы один спорный пример и запишите его в рабочий лист. Если эталон кажется неверным, обсудите его с наставником до написания промпта.

## Шаг 3. Допишите `dispatcher.py`

Найдите функцию `classify(text)`. Ветку учебного режима оставьте. Вместо `raise NotImplementedError(...)` реализуйте четыре действия:

1. Составьте `system`-инструкцию: категории, приоритет, уточнение и требование вернуть **только JSON**.
2. Передайте в `chat(...)` два сообщения: инструкцию с ролью `system` и обращение с ролью `user`.
3. Прочитайте `choices[0].message.content` из ответа API и разберите текст как JSON.
4. Проверьте: `category` входит в `CATEGORIES`, `priority` входит в `PRIORITIES`, `question` — строка. Если проверка не прошла, выдайте понятную ошибку через `ValueError`.

Итог функции должен иметь такой вид:

```json
{"category":"техника","priority":"обычный","question":"В каком кабинете не работает проектор?"}
```

Для ответа модели без уточнения поле `question` равно пустой строке `""`. Не подменяйте неверный ответ модели «успешным» результатом. Подсказки по коду есть в отдельном файле `03_подсказки_по_API_и_JSON.md`.

## Шаг 4. Проверьте живой запрос

Попросите наставника включить живой режим и настроить ключ. Перезапустите сервер, если наставник этого попросит. Отправьте через страницу:

1. «В кабинете 12 не включается проектор, урок уже начался» — ожидается `техника / высокий`.
2. «Что-то не работает, помогите» — ожидается `другое / обычный` и уточняющий вопрос.
3. Свой вымышленный пример — проверьте, согласны ли вы с ответом.

Ответ модели может отличаться от ожидаемого. Запишите расхождение; это материал для дальнейшей работы.

## Что считать готовым к концу занятия

- Страница открывается и принимает обращение.
- Живой ответ AllTokens проходит через сервер и содержит три поля в нужном формате.
- Есть пример, где модель задаёт уточняющий вопрос.
- Команда записала хотя бы один спорный или неверный ответ.
- Рабочий лист заполнен, и каждый участник может объяснить, что сделал.

Ручное исправление в интерфейсе и независимая проверка на новом наборе будут на следующих занятиях.
